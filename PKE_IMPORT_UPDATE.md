# PKE import and triparty gate-in update

Based on master 72f9d95.

## Dubai Import Files
Only the Dubai FZCO execution dashboard shows Import Files. The four tabs are Supplier purchase, Dubai sale to Pakistan, Import permit and LCs, and Supplier shipping documents. Pakistan clearance, Triparty gate-in and Local delivery tabs have been removed. Existing files and activity/document histories are preserved; old stages beyond the fourth stage display as complete.

Upload the supplier's own sales contract in Supplier purchase. Our purchase/sale contracts and invoices remain generated by the existing system. Other document and multiple-LC uploads remain available, including the shared permit/phyto reference. Documents remain optional during testing.

## Triparty gate-in in Pakistan Truck Movements
1. Book and lock the Dubai supplier purchase and Dubai sale to Kastros Pakistan, which is mirrored as Pakistan's purchase.
2. Create the Dubai import file for the supplier purchase. The Dubai sale can be linked in that file or through the truck assignment.
3. Record the physical Pakistan gate-in using the existing gatepass link.
4. In Truck Movements, choose the Dubai sale / Pakistan purchase trade, then select its supplier purchase / import file in the triparty selector.
5. Assign the truck. The Pakistan receipt, supplier-purchase link and both contracts' received/open quantities are committed in one transaction. A failure rolls back the allocation. Physical stock is counted once in Pakistan, never Dubai.
6. Partial receipts close only the quantity received. When the full booked quantities have been received, both related Dubai open quantities are zero. Payment balances remain independent.

Older allocated receipts missing a supplier link appear in an Existing PKE gate-ins panel in Truck Movements. Complete their references there; do not allocate the same truck again.

Subsequent Pakistan local sales and delivery are managed in Pakistan's existing screens, not in Dubai Import Files.

## LC document bypass
In Import permit and LCs, save the LC with its reference, then select it under Request LC document bypass. Describe the missing/non-compliant requirements and why payment may proceed. The request appears in LC bypass approvals and the shipment list shows its pending status.

Only an active user with role EXECUTION and head status can approve or reject. The decision, actor, time, LC terms, requirements, reason and review note are retained. A pending/rejected bypass blocks voucher or invoice-payment approval for the linked trade. Changing approved LC terms invalidates that approval and requires a new request. For multiple LCs, every current bypass must be approved. Approval permits the existing Finance workflow to continue; it does not itself send money or replace Finance approval/payment references.

Testing mode still permits missing documents where no bypass has been requested. An explicit bypass request always requires head approval.
